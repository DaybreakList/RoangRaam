# UAT Scenarios (TASK-59)

สคริปต์ทดสอบกับผู้ใช้จริง 10 สถานการณ์ ครอบคลุมลูกค้า, พนักงานต้อนรับ, แม่บ้าน, ผู้จัดการ และเจ้าของ
ใช้ใน TASK-60 (ให้คนนอกทีม 3 คนลองใช้) บั๊กที่พบส่งต่อ TASK-61

## สำหรับผู้คุมการทดสอบ

### เตรียมก่อนเริ่มผู้ทดสอบแต่ละคน

1. รีเซ็ตข้อมูลเดโม เพราะสถานการณ์จะเปลี่ยนข้อมูล และข้อมูลอิงกับ "วันนี้"

   ```
   docker compose exec web python manage.py seed_demo --reset
   ```

2. เช็คว่าระบบที่ใช้ทดสอบตั้งค่า Stripe โหมดทดสอบและ webhook แล้ว ถ้ายังไม่ได้ตั้ง สถานการณ์ที่ 2 จะยืนยันการจองไม่ได้
3. เปิดเบราว์เซอร์แบบไม่ระบุตัวตน และออกจากระบบทุกครั้งที่เปลี่ยนบัญชี
4. เตรียมหน้าเว็บของโรงแรมไว้ให้ผู้ทดสอบ: `/p/demo-riverside/search/` และหน้า login `/accounts/login/`

### บัญชีทดสอบ

รหัสผ่านทุกบัญชีคือค่า `SEED_DEMO_PASSWORD` ใน `.env` ผู้คุมบอกผู้ทดสอบเอง ห้ามเขียนลงเอกสารนี้

| บทบาท | อีเมล | โรงแรม |
| --- | --- | --- |
| เจ้าของ | `owner@example.com` | ริเวอร์ไซด์ และ ฮิลล์ท็อป |
| ผู้จัดการ | `manager.riverside@example.com` | ริเวอร์ไซด์ |
| พนักงานต้อนรับ | `frontdesk.riverside@example.com` | ริเวอร์ไซด์ |
| แม่บ้าน | `housekeeping.riverside@example.com` | ริเวอร์ไซด์ |

### กติกาตอนทดสอบ

- **ห้ามช่วยอธิบาย ห้ามชี้ปุ่ม** อ่านเฉพาะช่อง "งานที่ให้ทำ" ให้ผู้ทดสอบฟัง ถ้าถามว่าต้องกดตรงไหน ให้ตอบว่า "ลองดูตามที่คิดว่าใช่เลยครับ"
- ให้ผู้ทดสอบพูดสิ่งที่คิดออกมาระหว่างทำ
- จดจุดที่ลังเล กดผิด หรือไม่เข้าใจข้อความ แม้สุดท้ายจะทำสำเร็จก็ถือเป็นผลทดสอบ
- ถ้าติดเกิน 3 นาที ให้จดว่า "ทำไม่สำเร็จ" แล้วข้ามไปสถานการณ์ถัดไป
- ใช้ข้อมูลสมมติเท่านั้น ห้ามกรอกชื่อ เบอร์ หรือเลขบัตรจริงของผู้ทดสอบ

ข้อมูลสมมติที่ใช้กรอกได้: ชื่อ `ทดสอบ ระบบ`, อีเมล `uat.tester@example.com`, เบอร์ `0800000000`,
เลขบัตรประชาชน `1234567890123`, พาสปอร์ต `AA1234567`, บัตร Stripe ทดสอบ `4242 4242 4242 4242`
(วันหมดอายุเป็นวันในอนาคต CVC ใส่เลขใดก็ได้)

## สถานการณ์

ทำตามลำดับ เพราะสถานการณ์ที่ 4, 5 และ 6 ต่อเนื่องกัน

### 1. ลูกค้าจองห้องหลายห้องแบบจ่ายที่โรงแรม

- **บทบาท:** ลูกค้า (ไม่ต้องล็อกอิน) เริ่มที่หน้าโรงแรมริเวอร์ไซด์
- **งานที่ให้ทำ:** "คุณจะมาพักพรุ่งนี้ 2 คืนกับครอบครัว 3 คน ต้องการ 2 ห้อง และอยากจ่ายเงินตอนมาถึง ลองจองดู แล้วบอกว่าต้องใช้อะไรถ้าจะกลับมาดูการจองนี้"
- **ผลที่ต้องได้:**
  - เห็นเฉพาะห้องที่ว่างในวันที่เลือก พร้อมราคาและสิ่งอำนวยความสะดวก
  - หลังจองได้หน้ายืนยันที่มีรหัสการจอง สถานะยืนยันแล้ว
  - ยอดรวมเท่ากับราคารายคืนรวมกันของทุกห้อง
  - ผู้ทดสอบรู้ว่าต้องจดรหัสการจองไว้ (**ให้จดรหัสไว้ใช้ในสถานการณ์ที่ 3**)
- **ลองเพิ่ม:** เลือกวันเช็คเอาต์ก่อนวันเช็คอิน ต้องเห็นข้อความที่เข้าใจได้

### 2. ลูกค้าจองและจ่ายออนไลน์

- **บทบาท:** ลูกค้า
- **งานที่ให้ทำ:** "จองห้องราคาถูกที่สุด 1 คืนในสัปดาห์หน้า แล้วจ่ายเงินออนไลน์ให้เรียบร้อย" (ผู้คุมให้เลขบัตรทดสอบเมื่อถึงหน้าชำระเงิน)
- **ผลที่ต้องได้:**
  - ไปหน้าชำระเงินของ Stripe และยอดตรงกับตอนจอง
  - กลับมาเห็นว่าชำระเงินเรียบร้อย การจองได้รับการยืนยัน
  - ผู้คุมเช็คว่ามีอีเมลยืนยันถูกส่งออก
- **ลองเพิ่ม:** กดยกเลิกที่หน้า Stripe ต้องกลับมาเห็นสถานะรอชำระเงินและจ่ายใหม่ได้ ไม่เกิดการจองซ้ำ

### 3. ลูกค้าดูและยกเลิกการจองของตัวเอง

- **บทบาท:** ลูกค้า ใช้รหัสจากสถานการณ์ที่ 1
- **งานที่ให้ทำ:** "แผนเปลี่ยน คุณไม่มาแล้ว ลองยกเลิกการจองที่ทำไว้เมื่อกี้"
- **ผลที่ต้องได้:**
  - หาการจองเจอด้วยรหัสและอีเมล
  - มีขั้นตอนยืนยันก่อนยกเลิก ไม่มีค่าปรับ
  - สถานะเป็นยกเลิกแล้ว และห้องกลับมาค้นเจอในวันเดิม
- **ลองเพิ่ม:** ใส่รหัสผิดหรืออีเมลผิด ต้องไม่บอกข้อมูลการจองของใคร

### 4. พนักงานต้อนรับเช็คเอาต์แขก

- **บทบาท:** พนักงานต้อนรับ
- **งานที่ให้ทำ:** "แขกที่มีกำหนดออกวันนี้มายืนที่เคาน์เตอร์ เลือกมา 1 ราย คิดเงินให้เรียบร้อย ออกใบเสร็จ แล้วเช็คเอาต์ให้" (ผู้คุมจดเลขห้องไว้ใช้ในสถานการณ์ที่ 5)
- **ผลที่ต้องได้:**
  - เห็นรายการแขกที่ออกวันนี้
  - ปุ่มเช็คเอาต์ใช้ไม่ได้จนกว่าจะปิดบิล พร้อมบอกเหตุผล
  - ถ้ายังมียอดค้าง รับชำระได้ โดยยอดตรงกับค่าห้องรายคืน ถ้าจ่ายออนไลน์แล้วยอดคงเหลือเป็น 0
  - ปิดบิลแล้วได้เลขใบเสร็จ และดาวน์โหลด PDF ได้ ตัวเลขและ VAT ถูกต้อง
  - เช็คเอาต์แล้ว สถานะเปลี่ยน และห้องกลายเป็นรอทำความสะอาด
- **ลองเพิ่ม:** กดรับชำระซ้ำเร็ว ๆ ต้องบันทึกเงินครั้งเดียว

### 5. แม่บ้านทำความสะอาดห้อง

- **บทบาท:** แม่บ้าน
- **งานที่ให้ทำ:** "คุณเพิ่งทำความสะอาดห้องที่แขกเพิ่งออกเสร็จ บอกระบบให้เคาน์เตอร์รู้ และลองดูว่าชั้นนั้นเหลือห้องไหนต้องทำอีก"
- **ผลที่ต้องได้:**
  - เมนูมีแค่หน้าสถานะห้อง
  - ห้องรอทำความสะอาดอยู่บนสุด กรองตามชั้นและสถานะได้
  - กดแล้วห้องเป็นสะอาด และตัวเลขสรุปเปลี่ยนตาม
- **ลองเพิ่ม:** ใช้บนแท็บเล็ตหรือมือถือ ปุ่มต้องกดง่าย

### 6. พนักงานต้อนรับเช็คอินแขก

- **บทบาท:** พนักงานต้อนรับ
- **งานที่ให้ทำ:** "แขกที่จองไว้วันนี้มาถึงแล้ว ยื่นบัตรประชาชนให้ ช่วยเช็คอินให้เรียบร้อย ถ้าเช็คอินไม่ได้ ลองแก้ปัญหาดู"
- **ผลที่ต้องได้:**
  - เห็นรายการแขกที่เข้าวันนี้ พร้อมเลขห้องและสถานะห้อง
  - ถ้าห้องยังไม่สะอาด ปุ่มใช้ไม่ได้ บอกเหตุผล และไปหน้าสถานะห้องได้
  - กรอกเลขบัตรไม่ครบ 13 หลัก ต้องเห็นข้อความแจ้ง
  - เช็คอินแล้วสถานะเปลี่ยน และแขกอยู่ในรายการกำลังเข้าพัก
- **ลองเพิ่ม (ผู้คุมสังเกต):** ถ้าการจองที่เข้าวันนี้ได้ห้องเดียวกับแขกที่ยังไม่เช็คเอาต์ ลองทำความสะอาดห้องนั้นแล้วเช็คอิน ระบบควรห้ามหรือเตือน ถ้าเช็คอินผ่านได้ ให้จดเป็นบั๊ก

### 7. พนักงานต้อนรับย้ายห้องบน Tape Chart

- **บทบาท:** พนักงานต้อนรับ
- **งานที่ให้ทำ:** "ลูกค้าที่จะเข้าพักสัปดาห์หน้าขอเปลี่ยนเป็นห้องอื่นประเภทเดิม ลองย้ายให้" จากนั้น "ลองย้ายไปห้องคนละประเภทดู"
- **ผลที่ต้องได้:**
  - เห็นการจองทุกห้องบนตาราง พร้อมสถานะความสะอาด เลื่อนช่วงวันและกรองได้
  - ลากไปห้องประเภทเดียวกันที่ว่างได้ และวันกับราคาไม่เปลี่ยน
  - ห้องที่ไม่ว่างหรือคนละประเภทย้ายไม่ได้ พร้อมบอกเหตุผล
  - แขกที่เช็คอินแล้วย้ายไม่ได้
- **ลองเพิ่ม:** ลองบนแท็บเล็ตด้วยนิ้ว และลองใช้คีย์บอร์ด (Enter / Space)

### 8. ผู้จัดการปรับราคาและตั้งค่าโรงแรม

- **บทบาท:** ผู้จัดการ
- **งานที่ให้ทำ:** "ช่วงปีใหม่ขึ้นราคาห้อง Standard ทั้งสัปดาห์เป็น 2,500 บาท" จากนั้น "ใส่โลโก้โรงแรม และเปลี่ยนนโยบายการเข้าพัก"
- **ผลที่ต้องได้:**
  - แก้ราคาหลายวันพร้อมกันได้ และปฏิทินแสดงราคาใหม่
  - ลูกค้าค้นห้องช่วงนั้นเห็นราคาใหม่ ถ้าพักข้ามช่วงราคา ยอดรวมคิดตามราคาแต่ละคืน
  - การจองที่มีอยู่เดิมยอดไม่เปลี่ยน
  - โลโก้และนโยบายใหม่แสดงบนหน้าลูกค้า
- **ลองเพิ่ม:** ใส่ราคาติดลบ และอัปโหลดไฟล์ที่ไม่ใช่รูป ต้องเห็นข้อความที่เข้าใจได้

### 9. เจ้าของดูตัวเลขและเปรียบเทียบโรงแรม

- **บทบาท:** เจ้าของ
- **งานที่ให้ทำ:** "เดือนนี้โรงแรมริเวอร์ไซด์เป็นอย่างไรบ้าง แล้วโรงแรมไหนทำรายได้ต่อห้องดีกว่ากัน"
- **ผลที่ต้องได้:**
  - เห็น Occupancy, ADR, RevPAR และกราฟรายได้ของโรงแรม เลือกช่วงวันได้
  - สลับโรงแรมได้ และหน้าเปรียบเทียบแสดงทั้ง 2 โรงแรม
  - ผู้ทดสอบตอบคำถามได้จากหน้าจอ และเข้าใจความหมายของตัวเลข
- **ลองเพิ่ม (ผู้คุมเทียบ):** ล็อกอินเป็นผู้จัดการ ต้องไม่เห็นปุ่มและเข้าหน้าเปรียบเทียบไม่ได้

### 10. พนักงานพยายามเข้าส่วนที่ไม่มีสิทธิ์

- **บทบาท:** พนักงานต้อนรับ แล้วตามด้วยแม่บ้าน (ผู้คุมบอก URL ให้พิมพ์)
- **งานที่ให้ทำ:** "ลองพิมพ์ที่อยู่นี้" แล้วเปิดทีละรายการ
  - `/p/demo-hilltop/frontdesk/today/` (โรงแรมอื่น)
  - `/p/demo-riverside/dashboard/` (ไม่มีสิทธิ์)
  - แม่บ้าน: `/p/demo-riverside/frontdesk/today/` (ไม่มีสิทธิ์)
- **ผลที่ต้องได้:**
  - ไม่เห็นข้อมูลของโรงแรมอื่นหรือส่วนที่ไม่มีสิทธิ์
  - โรงแรมอื่นได้หน้าไม่พบ ส่วนที่ไม่มีสิทธิ์ได้หน้าปฏิเสธ
  - ผู้ทดสอบเข้าใจข้อความ และมีทางกลับไปทำงานต่อ
