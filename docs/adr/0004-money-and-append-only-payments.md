# ADR 0004: เงินเป็น Decimal, ราคารายคืน, รายการเงินแบบเพิ่มอย่างเดียว

- **สถานะ:** ใช้อยู่
- **วันที่:** ตุลาคม 2026 (Sprint 2–3)

## บริบท

ระบบรับเงินจริงผ่าน Stripe (โหมดทดสอบ) และที่เคาน์เตอร์ ออกใบเสร็จ และคำนวณ KPI จากรายได้
ราคาห้องเปลี่ยนรายวันตามปฏิทินราคา และโรงแรมแก้อัตรา VAT ได้เอง
ถ้าคำนวณด้วย float หรือแก้ทับรายการเงินเดิม ยอดจะคลาดเคลื่อนและตรวจย้อนหลังไม่ได้
Stripe ยังส่ง webhook ซ้ำได้ และผู้ใช้อาจกดปุ่มชำระซ้ำ

## การตัดสินใจ

- เงินใช้ `Decimal` ทั้งใน model และการคำนวณ ส่งใน JSON เป็น decimal string (`COERCE_DECIMAL_TO_STRING`)
  และแปลงเป็นสตางค์เฉพาะตอนส่งให้ Stripe
- ราคารวมคิดทีละคืนจาก `DailyRate` และบันทึกราคาของแต่ละคืนไว้ใน `BookingNightRate` ตอนจอง
  แก้ปฏิทินราคาภายหลังจึงไม่เปลี่ยนการจองที่มีอยู่
- `Payment` (CHARGE / REFUND) และ `Receipt` เป็นแบบเพิ่มอย่างเดียว: `save()` ปฏิเสธการแก้ และ `delete()` ปฏิเสธการลบ
  การคืนเงินคือการเพิ่มแถว REFUND ใหม่
- กันเงินซ้ำด้วย unique (`property`, `provider_ref`) และ (`property`, `idempotency_key`)
  webhook ที่มาซ้ำจึงเจอแถวเดิมแทนการเพิ่มใหม่ และ webhook ต้องผ่านการตรวจลายเซ็นของ Stripe
- การจองที่ยังไม่จ่ายถือห้องไว้ 60 นาที (`PAYMENT_WINDOW`) แล้วถูกปล่อย
- ใบเสร็จเก็บอัตรา VAT และยอดภาษี ณ ตอนปิดบิล เลขที่ใบเสร็จเรียงต่อโรงแรม และเช็คเอาต์ได้หลังปิดบิลแล้วเท่านั้น

## ผลที่ตามมา

- **ดี:** ยอดเงินตรวจย้อนหลังได้ทุกรายการ ยอดคงเหลือใน Folio คำนวณจากรายการทั้งหมด ไม่มีค่าที่เก็บซ้ำแล้วไม่ตรงกัน
- **ดี:** เทสต์ webhook ซ้ำและกดซ้ำยืนยันว่าไม่ตัดเงินสองครั้ง (US-07)
- **ข้อเสีย:** แก้รายการผิดไม่ได้ ต้องเพิ่มรายการชดเชย
- **ข้อจำกัดที่รู้อยู่:** Dashboard KPI แสดงรายได้แบบไม่รวม VAT โดยใช้อัตรา VAT **ปัจจุบัน** ของโรงแรม
  เพราะการจองไม่ได้เก็บอัตรา VAT ไว้ ถ้าโรงแรมแก้อัตรา VAT ตัวเลขรายได้ย้อนหลังใน Dashboard จะเปลี่ยนตาม
  (ใบเสร็จไม่เปลี่ยน เพราะเก็บอัตราไว้แล้ว) แก้ได้ด้วยการเก็บอัตรา VAT ใน `Booking` ตอนจอง ซึ่งต้องเพิ่ม migration
